# Witle-Course
This repository stores data analysis course work built as part of the Witle Academy Data Analytics Programme. 

## Overview
I designed the database structure for WitleShop (Pty) Ltd, a fictional South African online retailer. It sells electronics, clothing and home appliances through a web and mobile platform.

## The Problem
WitleShop was growing fast and needed one database to manage customers, products, orders, payments, deliveries and suppliers. I had to turn a set of written business rules into a clear data model with as little repeated data as possible. The rules included things like "a customer can have multiple delivery addresses" and "one order has exactly one payment."

## Approach
1.	Requirements analysis: went through the case study and picked out entities, attributes and business rules.
2.	Entity identification: defined 8 entities: Customer, Address, Category, Supplier, Product, Order, Payment and Deliveries.
3.	Keys and constraints: each table has a primary key, and foreign keys connect the related tables. Customer Email is unique.
4.	Relationships and cardinality: mapped all the 1:1, 1:M and M:N relationships.
5.	ERD: drew the full diagram on Draw.io, showing every entity, attribute, key and relationship.

## Skills Demonstrated 
•	Conceptual and logical database design
•	Entity-relationship modelling (Draw.io)
•	Primary, foreign, and unique keys
•	Cardinality and how optional or required each relationship is
•	Turning business requirements into a technical design
•	Technical documentation
